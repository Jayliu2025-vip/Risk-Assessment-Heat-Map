# 审计报告风险评估 Windows 桌面端设计

**日期：** 2026-09-02  
**状态：** 用户已确认，进入实施计划阶段
**适用版本：** 审计风险评估热力图谱 v1.2 后续增量

## 1. 目标

在现有项目中增加一个 Windows 桌面端入口，让用户上传 PDF 或 Word 审计报告，由系统在本地提取文字，必要时执行 OCR，再调用用户配置的 OpenAI 兼容大模型识别审计发现、匹配现有风险点并提出建议评分。用户复核确认后，结果进入现有风险登记册，并继续使用既有的八维评分、控制折减、热力图、趋势和报告能力。

新增能力是现有风险评估流程前端的“报告转结构化风险”环节，不是独立知识管理系统。

## 2. 明确不做的范围

本阶段及项目后续均不建设：

- 知识库、RAG、向量数据库或语义检索；
- 面向历史报告库的聊天问答；
- 大规模报告归档、标签管理或全文搜索；
- 未经人工确认自动修改正式风险台账；
- 由大模型自行改变权重、阈值、控制折减规则或最终计算公式；
- 为不同模型厂商分别开发专用 SDK 适配器。

SQLite 仅用于保存本机分析任务、待复核发现和操作状态，不承担知识库或历史语义检索功能。

## 3. 核心原则

1. **现有项目优先复用。** 保留现有 HTML 风险热力图界面、Python 评分引擎、Excel 真源、CSV 交换格式和 PDF/PNG 输出。
2. **本地提取优先。** PDF 和 Word 先在本机提取文本；仅对没有可用文字层的页面执行 OCR。
3. **视觉模型只为提取兜底。** 本地提取质量不足时，才把问题页面图片或原文件交给支持视觉输入的模型。
4. **大模型始终负责业务理解。** 无论文本来自直接提取还是 OCR，审计发现识别、风险匹配和建议评分都由大模型完成。
5. **确定性引擎负责计算。** 大模型只给出可能性和八维影响建议分；综合影响、固有风险、控制折减、剩余风险与等级继续由现有 Python 评分逻辑计算。
6. **人工确认是写入门槛。** 模型结果只能进入待复核区，未经用户确认不得进入正式风险登记册。
7. **最少留存。** 不复制原始报告，不长期保存完整提取文本，不记录完整模型请求和响应。
8. **不覆盖原工作簿。** 正式写入时生成带日期时间的新版本，保留原始 Excel 文件。

## 4. 技术架构

采用 **Python + Windows WebView2** 路线，优先通过轻量桌面壳复用现有网页资源，而不是重写 WinUI 界面。

```text
Windows 桌面应用
├── WebView2 界面
│   ├── 新增：审计报告评估四步向导
│   └── 复用：风险维护、评分参数、热力图、趋势和优先级页面
└── Python 本地后端
    ├── 文件读取与页面结构保留
    ├── 扫描页检测与 OCR
    ├── 提取质量检查与视觉模型兜底
    ├── OpenAI 兼容模型客户端
    ├── 模型输出校验与待复核发现管理
    ├── 现有确定性评分引擎
    ├── SQLite 本地任务状态
    └── Excel / CSV / PNG / PDF 输出
```

桌面壳负责原生文件选择、窗口生命周期、Windows 凭据访问和前后端通信。Python 后端负责所有文件处理、模型调用和正式数据写入。网页前端不直接持有 API Key，也不直接读取或改写工作簿。

## 5. 处理流程

### 5.1 文件进入

第一版支持：

- 含文字层的 PDF；
- 扫描 PDF；
- DOCX Word 文档；
- 同时包含正文、表格和图片页的混合文档。

DOC 等旧版二进制 Word 文件不直接解析。界面明确提示用户先另存为 DOCX 或 PDF，避免引入 Office 自动化和格式兼容风险。

### 5.2 文本获取

```text
上传文件
  ↓
按页或结构块执行本地文字提取
  ↓
判断页面是否有足够可用文本
  ├─ 有：保留文本、页码和结构位置
  └─ 无：对该页执行 OCR
          ↓
      再次检查提取质量
          ├─ 合格：进入大模型分析
          └─ 不合格：视觉模型读取问题页面
```

“质量不足”包括空白输出、可打印字符比例过低、明显乱码、页面只有图片但没有识别文本等可确定检测条件。系统不以单一 OCR 置信度决定业务结论；低质量页面统一标记为需要人工核对。

### 5.3 大模型分析

系统把带页码的规范化文本交给用户选择的 OpenAI 兼容模型。模型完成：

- 将报告拆分成独立审计发现；
- 提炼每条发现的事实摘要；
- 匹配现有风险编号和 12 个风险领域，或建议新增风险；
- 提出发生可能性和八个影响维度的 1–5 分建议；
- 给出一段合并后的评分依据；
- 标识证据不足、数字冲突或需要人工核对的内容。

模型不能生成最终综合影响、固有风险、剩余风险或风险等级作为正式结果。即使响应中包含这些数值，程序也忽略并以现有评分引擎重新计算。

### 5.4 人工复核与正式写入

用户可以修改、合并、拆分、接受或排除待复核发现。多个发现匹配同一风险时，系统不得自动生成重复风险，而是要求用户选择：

- 合并到现有风险；
- 作为新的独立风险；
- 暂不纳入。

用户确认风险映射、评估期间、整改状态和当前控制有效性后，系统才生成正式风险记录。历史报告只能说明报告形成时的事实，不能单独证明当前剩余风险；当前控制措施和整改情况必须由用户确认。

写入前展示变更预览。写入时以当前正式工作簿为模板，生成 `audit_risk_register_YYYYMMDD_HHMM.xlsx`，原工作簿保持不变。新版工作簿继续通过现有导出、评分和报告流程生成 CSV、热力图与高管报告。

## 6. 精简数据结构

### 6.1 报告分析任务

只保存：

| 字段 | 含义 |
|---|---|
| `task_id` | 本机唯一任务编号 |
| `file_name` | 原文件名，不保存完整本地路径 |
| `file_hash` | 用于识别同一文件和防止误写 |
| `created_at` | 任务创建时间 |
| `status` | 提取中、分析中、待复核、已完成、失败 |
| `model_profile` | 用户选择的模型配置名称，不含 API Key |
| `extraction_method` | 文本提取、OCR、视觉兜底或混合 |

不保存报告副本、完整模型请求、完整模型响应或长期过程日志。规范化文本和页面图片属于临时文件，任务完成、取消或失败清理后删除。

### 6.2 待复核审计发现

只保存：

| 字段 | 含义 |
|---|---|
| `finding_id` | 当前任务内唯一编号 |
| `title` | 发现标题 |
| `fact_summary` | 事实摘要；单位、金额等重要信息写在这里 |
| `source_page` | 来源页码或 Word 结构位置 |
| `source_excerpt` | 支撑判断的关键原文 |
| `matched_risk_id` | 匹配的现有风险编号；建议新增时可为空 |
| `domain` | 现有 12 个风险领域之一 |
| `likelihood` | 建议可能性分，1–5 或空 |
| `impact_scores` | 八维建议分，各维 1–5 或空 |
| `rationale` | 合并后的评分依据 |
| `needs_review` | 是否存在提取质量或判断依据问题 |
| `review_status` | 待确认、已接受、已排除 |

不单独保存单位、金额、OCR 置信度、模型置信度或八个维度各自的证据字段。

## 7. 用户流程

桌面端提供四步向导：

### 第一步：上传报告

用户拖入或选择 PDF/DOCX 文件，选择评估期间和模型配置，点击“开始分析”。已验证的模型配置默认复用。

### 第二步：本地提取

系统自动完成文字提取、扫描页 OCR、质量检查和必要的视觉模型兜底。界面仅显示阶段进度、失败原因和需要人工核对的页码，不向普通用户暴露 OCR 参数或提示词。

### 第三步：复核审计发现

左侧显示原报告对应页面或 Word 内容位置，右侧显示精简的待复核发现字段。用户可以：

- 编辑标题、事实摘要、来源原文和建议分；
- 修改风险编号和风险领域；
- 合并或拆分发现；
- 接受或排除发现；
- 保留证据不足维度为空。

### 第四步：进入现有风险评估

用户确认风险映射、整改状态和当前控制后查看变更预览。系统生成新版 Excel，并把确认数据交给现有评分引擎和展示页面。用户随后继续使用现有热力图、趋势、优先级和报告输出。

## 8. 模型配置

第一版采用统一的 OpenAI 兼容接口，不为厂商编写独立适配器。每个模型配置仅包含：

- 配置名称；
- 服务地址；
- 模型名称；
- API Key；
- 是否支持视觉输入。

API Key 使用 Windows 凭据库保存。SQLite 和日志只保存模型配置名称，不保存服务密钥。设置页提供“测试连接”，成功后才能用于报告分析。

兼容接口并不假定支持统一的 PDF/Word 文件上传，因此主流程始终以本地提取后的文本为标准输入；仅在用户配置声明支持视觉能力时，才允许发送低质量问题页面的图片作为兜底。

## 9. 安全与异常处理

- 界面始终展示当前模型配置和服务地址的主机名，让用户知道内容将发送到哪里。
- 报告内容作为不可信资料放入模型输入，报告中的命令、提示词或要求不得改变系统指令和输出结构。
- 模型不能调用工具、访问外部链接或修改本地文件。
- 模型响应必须通过结构校验：风险领域必须来自现有清单，建议分只能为 1–5 或空，风险编号必须匹配现有编号或明确标为新增建议。
- 空证据、相互矛盾的数字、低质量页面和无法定位的原文必须设置 `needs_review`。
- OCR 失败、模型超时、限流、连接失败和 JSON 格式错误时，只重试失败阶段，保留已完成人工修改。
- 正式写入前必须有变更预览和用户确认；写入使用新文件名，禁止静默覆盖原工作簿。
- 日志不记录 API Key、报告正文、模型完整请求或模型完整响应。
- 任务完成、取消或清理失败任务时删除临时文字和页面图片；若删除失败，界面明确列出残留位置供用户处理。

## 10. 测试与验收

所有自动测试使用虚构报告和本地模拟模型，不读取真实审计报告，也不调用真实付费接口。

### 10.1 文件读取测试

准备文字型 PDF、扫描 PDF、DOCX 和含表格 DOCX 的虚构样例，验证正文顺序、页码或结构位置、表格文字、扫描页检测、OCR 路由和视觉兜底条件。

### 10.2 模型接口测试

使用本地模拟 OpenAI 兼容服务覆盖：

- 合法结构化响应；
- 非法 JSON；
- 超时和限流；
- 无视觉能力；
- 低质量页面的视觉兜底；
- 模型返回非法领域、越界分数或不存在风险编号。

### 10.3 风险转换测试

验证：

- 无证据维度保持为空；
- 多个发现匹配同一风险时进入人工合并流程；
- 被排除的发现不能写入正式数据；
- 模型给出的最终风险值被忽略；
- 确认后的建议分由现有评分引擎重新计算；
- 未确认当前控制时不把历史控制缺陷直接当成当前控制分。

### 10.4 现有项目回归

保留并运行现有全部测试。新增集成测试覆盖：待复核发现确认、风险记录转换、新版工作簿生成、CSV 导出以及 Python/网页评分一致性。桌面端不得改变 v1.2 的八维模型、阈值、分领域权重或控制折减规则。

### 10.5 Windows 端到端验收

使用一份包含三条虚构发现且至少一页为扫描件的报告完成：

```text
安装应用
→ 配置本地模拟模型
→ 上传报告
→ 自动提取与 OCR
→ 得到三条待复核发现
→ 修改一条、合并一条、排除一条
→ 确认当前控制
→ 生成新版 Excel
→ 查看风险等级和热力图
```

同时验证：

- 原工作簿哈希保持不变；
- 新版工作簿能被现有导出脚本读取；
- API Key和报告正文未进入 SQLite 或日志；
- 临时文本和页面图片已清理；
- 当前完整自动测试套件通过；
- Windows 安装包在未预装 Python 的测试环境中可以启动并完成上述流程。

## 11. 第一版完成标准

满足以下条件才视为第一版完成：

1. Windows 用户通过安装包启动应用，不需要安装 Python或使用命令行。
2. 文字型 PDF、扫描 PDF 和 DOCX 都能进入同一分析流程。
3. 本地提取优先，扫描页自动 OCR，低质量问题页可使用视觉模型兜底。
4. 用户可以通过 OpenAI 兼容接口配置云端或本地模型服务。
5. 模型输出形成精简的待复核发现，不直接进入正式风险台账。
6. 用户可以修改、合并、拆分、接受和排除发现。
7. 确认后的数据进入现有评分体系，最终分数由现有确定性引擎计算。
8. 写入产生新版 Excel，原工作簿不被覆盖。
9. 不提供知识库、RAG、向量检索或历史报告问答能力。
10. 自动测试、Windows 端到端流程、数据最少留存和临时文件清理全部通过验收。
