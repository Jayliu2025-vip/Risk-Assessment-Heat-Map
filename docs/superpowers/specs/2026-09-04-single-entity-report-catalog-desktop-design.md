# 单主体审计报告目录与风险评估批次设计

**日期：** 2026-09-04
**状态：** 用户已通过交互原型确认，进入实现
**适用项目：** Risk Assessment Heat Map Windows 桌面端

## 1. 目标与首版边界

桌面端默认进入空的报告目录。用户为一个被审计主体设置本地信息目录，逐份选择 PDF/DOCX 审计报告，完成本地提取、模型辅助识别和人工复核后，仅把项目相关的结构化信息保存到该目录。用户随后可按上传日期和审计项目筛选并选择一份或多份报告，形成一次风险评估批次，确认当前风险、整改和控制后生成新的版本化工作簿与风险图谱。

首版一个信息目录严格对应一个被审计主体。集团组织树、跨主体选择和集团汇总图谱不进入本次实现。数据结构保留稳定 `entity_id`，但不能在已有报告的目录中直接改换主体。

桌面端不自动加载示例数据，隐藏“载入内置示例”。虚构数据仅存在于自动测试和独立原型，不进入生产桌面状态。

## 2. 工作区与文件结构

用户首次设置一个总目录并确认主体名称。目录保存：

```text
<catalog-root>/
├── workspace.json
├── catalog-index.json
├── projects/<project-id>--<safe-name>/<upload-date>/<report-id>/report-vN.json
├── batches/<batch-id>/batch.json
└── trash/<deleted-at>--<report-id>/report-vN.json
```

`report-vN.json` 是报告结构化信息真源；`catalog-index.json` 是可重建索引。应用自身 SQLite 只保存目录位置、模型配置和尚未归档的临时任务，不作为报告目录真源。

应用不复制原始 PDF/DOCX，不保存原始完整路径、完整提取正文、页面图片、API Key 或完整模型请求响应。每份报告记录文件名、SHA-256、上传时间、可选报告日期、审计项目、识别版本、模型配置名称、提取方式、结构化发现和人工复核状态。每条发现保留来源报告、来源发现编号、页码或 Word 位置和有限关键摘录。

## 3. 报告进入目录

用户点击“添加审计报告”，依次选择：

1. 原始 PDF/DOCX；
2. 当前正式工作簿，用于给模型提供最小化的现有风险目录；
3. 审计项目；
4. 已验证模型配置。

上传日期由系统记录。报告日期为可选字段，可由识别结果建议但必须由用户确认。当前正式工作簿仅用于风险匹配参考，不在此阶段写入。

提取和分析沿用现有安全链路。用户在三栏界面中复核发现；所有发现均已接受或排除后，才能执行“保存到报告目录”。保存成功后清理原始文件运行时映射和临时页面/全文，只保留结构化记录。

## 4. 报告目录

报告目录按上传日期倒序展示：上传日期、审计项目、报告名称、报告日期、识别版本、状态和发现数量。用户可按报告名称、审计项目和上传日期筛选，并选择一份或多份已完成报告。

普通删除把报告目录移动到同一根目录的 `trash`，可恢复；“清空报告列表”经数量确认后移动全部活动报告。普通删除不得删除原报告、项目名称、历史批次或生成工作簿。所有移动和删除前必须验证源与目标解析路径都位于当前目录根内。

## 5. 多报告风险评估批次

用户选择一份或多份报告后，选择当前正式工作簿并填写唯一的目标评估期间。系统把所选报告的确切识别版本复制为一个临时批次任务，给每条发现分配批次内唯一编号，并保留来源报告、来源发现编号、上传日期和来源位置。

若所选工作簿不再包含报告曾匹配的风险编号，该发现改为待重新匹配，不能静默写入。批次只使用已接受且未被排除的报告发现。

来自不同报告、但指向同一风险的发现显示在“相似发现处理”中。推荐选项为“为同一风险的两条证据”：最终工作簿只形成一条风险记录，但所有报告、页码和事实依据分别保留。其他选项为“分别作为两项风险”和“本次暂不处理”。关联为同一风险不得删除目录中的原发现，也不得平均模型建议评分；用户必须重新确认当前可能性、八维影响、责任部门、整改状态和控制措施。

写入前继续使用现有预览令牌和工作簿哈希绑定。写入生成 `audit_risk_register_yyyyMMdd_HHmm.xlsx`，不覆盖来源工作簿。成功后保存不可变 `batch.json`，记录所用报告版本、决策、来源工作簿哈希和输出文件标识，再加载实际生成期间进入风险图谱。

## 6. 桌面界面

桌面端使用四个独立工作区：报告目录、识别与复核、风险评估批次、风险图谱。报告流程不再叠在现有热力图上方。

- 报告目录是生产桌面默认首页；空目录不展示风险卡片或示例图谱。
- 识别复核使用报告/发现列表、来源摘录、人工复核表单三栏布局；各栏独立滚动，保存、接受、排除、合并和拆分操作固定在视口内。
- 风险评估批次展示所选报告版本、相似发现关系、当前工作簿、目标期间、责任部门、整改和控制确认。
- 只有成功写入工作簿后才启用风险图谱入口。桌面风险图谱复用现有确定性评分和可视化页面。
- 步骤导航真实可返回；没有模型时显示明确配置动作，不展示无解释的空白下拉框。

## 7. 异常与完整性

- 目录缺失、不可写、主体不匹配或索引损坏时停止写入并给出可恢复提示。
- 索引可从有效 `report-vN.json` 重建；损坏记录不自动覆盖。
- 报告保存采用同目录临时文件加原子替换。
- 批次创建、预览和写入沿用任务锁、工作簿哈希和一次性预览令牌。
- 删除、清空和目录迁移不得基于未验证的相对路径、通配符或目录外符号链接。
- 既有浏览器演示模式保留手动“载入内置示例”，但不再自动加载；桌面模式隐藏该按钮。

## 8. 验收

自动测试仅使用虚构报告、虚构目录和本地模拟模型。至少覆盖：单主体目录初始化、主体不可静默变更、目录外路径拒绝、报告结构化保存、无原路径/正文泄漏、列表筛选数据、单条移入回收站、清空列表、多报告批次来源保留、失效风险编号待重映射、同一风险多证据、版本化工作簿写入、默认空状态、桌面隐藏示例、复核操作栏首屏可见以及 1120×720 无横向溢出。
