# 审计使用者优先 README 设计

**日期：** 2026-09-05
**状态：** 待用户确认
**适用范围：** Risk Assessment Heat Map 仓库首页 README

## 1. 目标

把仓库首页从“开发者工具三件套说明”改为审计使用者可以直接理解和执行的产品入口。读者应在首页首屏明确知道：这个项目用于从审计报告中提取、复核并形成结构化风险信息；Windows 桌面端默认不加载示例；首版仅评估一个主体；使用者可以选择一份或多份报告形成风险图谱。

README 不承担完整操作手册、开发设计文档或宣传文章的职责。详细操作继续链接到 `docs/使用手册.md`，技术验证继续链接到 `docs/desktop-acceptance.md`。

## 2. 信息架构

README 按审计使用者完成任务的顺序组织：

1. 项目名称、一句话定位和当前版本。
2. Windows 桌面端适用对象、系统要求和安装入口。
3. 从创建单主体信息目录到生成风险图谱的完整流程。
4. 报告目录的日期、项目筛选和一份或多份报告选择方式。
5. 相似发现处理，突出“为同一风险的两条证据”的推荐规则。
6. 数据保存、删除、清空、回收站和隐私边界。
7. 评分模型、输出文件和人工复核责任。
8. 当前支持范围、暂不支持范围和使用限制。
9. 面向开发者的环境、测试、打包和目录结构附录。
10. 许可证与第三方许可说明。

## 3. 内容原则

- 使用审计业务语言解释流程，首次出现技术术语时给出实际含义。
- 先讲安装与使用，再讲架构、命令和文件结构。
- 桌面端快速开始从空报告目录开始，不把内置示例作为默认入口。
- 明确一个信息目录只能对应一个被审计主体；集团组织树、跨主体选择和集团汇总属于后续规划。
- 明确上传日期是报告列表的主要日期，识别出的报告日期仅作为附加信息。
- 明确目录只保存人工复核后的项目相关结构化信息，不保存原报告、原路径、完整正文、页面图片或 API Key。
- 明确历史审计发现不是当前剩余风险结论；当前控制、整改状态和正式评分必须由使用者重新确认。
- 不出现任何私有发布材料、相关文件名或本地保存链接。

## 4. 事实边界

README 只陈述当前代码、测试、使用手册和验收记录能够证明的能力。不得把以下事项写成已实现：集团多主体管理、知识库、RAG、向量检索、历史报告问答、自动审批、无需人工确认的正式评分、彻底删除 Git 历史中的私有材料。

测试状态写为当前已验证的 250 项 Python 测试和 7 项 Playwright 流程。清洁 Windows 无 Python 环境与物理断网验收仍标为待完成，不使用“全面发布完成”等超出证据的表述。

## 5. 快速开始设计

桌面端快速开始保持四步：

1. 安装并打开 Windows 桌面端，指定结构化信息目录和唯一被审计主体。
2. 添加 PDF 或 DOCX 报告，完成模型连接、内容识别和人工复核。
3. 按上传日期与审计项目选择一份或多份报告，处理相似发现并确认当前控制。
4. 预览变更，生成新的版本化 Excel 工作簿，再查看风险图谱。

网页端与 Python/Excel 工作流保留为补充入口，不再占据首要快速开始位置。浏览器演示只能由使用者显式加载示例；桌面端不暴露示例入口。

- 不包含任何私有发布材料或指向本地私有目录的链接。
- 不包含已失效的“24 项测试”或把示例作为推荐入口的描述。
- 所有仓库内链接有效，Markdown 差异检查通过。
- 文档契约测试、全仓库私有发布材料检查和 README 关键事实检查通过。
