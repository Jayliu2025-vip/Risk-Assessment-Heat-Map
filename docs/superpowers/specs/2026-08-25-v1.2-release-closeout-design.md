# v1.2 发布收尾设计

## 背景

当前 `main` 分支已提交 v1.1 基线与权威评分锚点，本地工作区继续完成了八维影响模型升级：新增战略影响、数据安全、健康安全，支持不适用维度留空及有效权重重归一化，并同步扩展 Excel、Python、网页、示例数据和报告产物。

本轮核心实现已有 24 项单元测试覆盖，Excel、CSV 与配置数据一致，但发布口径、端到端验收和仓库清洁度尚未收口。

## 可选方案

1. 仅修正明显旧文字，不调整版本号。改动最小，但八维升级仍沿用 v1.1，发布边界不清晰。
2. 作为 v1.2 完整收尾。统一文案和版本号，完成三端验收，清理非项目日志后提交。此方案范围清楚、风险最低，采用该方案。
3. 升级为 v2.0 并重构网页或评分引擎。改动范围明显超出当前收尾目标，不采用。

## 目标状态

- 所有用户可见文字统一为八维影响模型。
- 示例数据口径统一为每期 24 条风险、覆盖 4 大类 12 领域。
- 测试数量统一为 24 项。
- 手册、代码、配置和网页统一使用版本号 `1.2`。
- Excel 真源、CSV、配置、Python 评分结果和网页评分公式保持一致。
- 报告图集与 PDF 能从当前数据重新生成，关键输出文件完整。
- 浏览器核心流程可用：载入示例、切换期间、查看热力图、打开设置和数据维护区域。
- `logs/` 等与项目无关的运行日志不进入版本库。
- 最终提交只包含本轮八维升级及其必要收尾，不夹带无关改动。

## 修改范围

### 文案一致性

检查并修正 `README.md`、`docs/使用手册.md`、`tools/build_excel.py`、`tools/generate_report.py`、`web/risk_heatmap.html` 中残留的“五维”“16 条”“6 个领域”“21 项”等旧口径。权威来源引用中的“五维”若特指原五个维度，也改写为不产生歧义的“影响维度”。

### 版本一致性

将以下发布口径统一为 `1.2`：

- `tools/common.py` 默认配置与模块说明；
- `tools/export_from_excel.py` 导出配置版本；
- `data/export/config.json`；
- `docs/使用手册.md`；
- 网页可见版本标识（如已有）；
- Excel 工作簿内的版本说明，由生成脚本重建后同步。

### 验收

验收分为四层：

1. 单元测试：运行全部 24 项评分测试。
2. 数据一致性：比对 Excel 与两个期间 CSV、控制点和配置。
3. 生成链路：从 Excel 导出数据，并重新生成图集与 PDF。
4. 用户界面：在本地浏览器打开网页，验证载入示例、期间切换、热力图、设置和数据维护入口。

Excel 公式将通过结构检查和工作簿重建验证；如果本机无法自动驱动 Excel 桌面版，则明确记录“未进行 Excel 桌面重算”，不把结构检查描述为桌面兼容性通过。

## 清理与提交策略

- 删除当前未跟踪的 `logs/` 目录；这些文件来自无关的 IMA MCP 启动失败日志，可由外部工具重新生成。
- 在 `.gitignore` 中加入 `/logs/`，防止再次污染仓库。
- 不批量改写所有文件行尾；仅确认 `git diff --check` 无实际空白错误，避免制造无关差异。
- 设计说明、实施计划和最终功能改动分阶段提交，最终提交信息明确标注 v1.2 八维模型升级。

## 成功标准

- 全仓搜索不再发现代表当前模型的旧口径。
- 24 项单元测试全部通过。
- Excel、CSV、控制点与配置逐项一致。
- 报告命令退出码为 0，预期 PNG 与 PDF 均存在且非空。
- 网页核心流程通过浏览器验收，控制台无阻断性错误。
- `git status` 不含 `logs/`，最终提交后工作区干净。
