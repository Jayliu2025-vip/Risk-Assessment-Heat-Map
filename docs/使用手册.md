## 1. 项目是什么

一套**通用内审风险评估工具**，围绕"风险热力图谱"提供三种使用形态，共用同一评分模型、同一份数据，三端数值完全一致：

| 形态 | 载体 | 适合场景 |
|---|---|---|
| **Excel 工作簿** | `audit_risk_register.xlsx` | 日常维护数据（唯一真源）、审计人员手工打分 |
| **Python 脚本** | `tools/` 目录 | 批量出图、生成 PDF 高管简报、集成到自动化流程 |
| **网页端** | `web/risk_heatmap.html` | 汇报演示、交互式探查、临时编辑、打印存 PDF |

核心能力：

- **多因素加权评分**：可能性 + 八维影响（经济损失/合规法律/运营中断/声誉舆情/舞弊风险/战略影响/数据安全/健康安全）
- **短板效应控制折减**：每条风险挂多条控制点，按"最弱控制点"折算剩余风险
- **固有 / 剩余双热力图**：直观展示控制措施带来的风险改善
- **多期趋势对比**：两期剩余风险哑铃图，红=恶化、绿=改善
- **年度审计优先级**：按剩余风险自动排序 + 审计频次建议

## 3. 评分模型详解

### 3.1 计算公式

```
综合影响 I = MAX( Σ(wᵢ×维度ᵢ)/Σ(已打分维度的wᵢ) , 一票否决系数 × 最高已打分维度 )
固有风险   = 发生可能性 L × I
控制分     = MIN(关键控制点得分)                     ← 短板效应
剩余风险   = 固有风险 × (1 − 折减系数[控制分])
控制挽回率 = (固有风险 − 剩余风险) / 固有风险
```

- **八个影响维度**：经济损失、合规法律、运营中断、声誉舆情、舞弊风险、
  战略影响、数据安全、健康安全（各 1-5 分）；
- **维度可留空（=不适用）**：留空维度不参与加权，权重在已打分维度上重新归一化
  ——每条风险可自定义"适用哪些维度"，但至少打一个维度；
- 加权权重 wᵢ **按风险所属领域**取分领域权重矩阵（12 领域 × 8 维，见 4.2），
  未列领域用"全领域默认"行；
- **一票否决下限**（默认 0.75）：任一已打分维度打到 5 分，综合影响不低于 3.75；
- 综合影响 I ∈ [1, 5]，固有风险 ∈ [1, 25]，剩余风险 ∈ [0, 25]；
- **无控制点的风险不做任何折减**（剩余 = 固有）——未验证的控制不给信用；
- 所有中间值保留两位小数。

### 3.2 打分锚点（权威标准版）

> **维度独立性原则**：各维度只评估其**专属后果**——经济损失维度不重复计入
> 舞弊造成的损失，声誉维度不重复计入合规处罚带来的舆情。避免维度间重复计分，
> 这是八维加权结果可信的前提。
>
> 金额锚点以国资委资产损失分级为基准刻度，适合央企/国企；非国有企业可按
> 营收规模等比例缩放（建议保持相邻档位 5~10 倍跨度），缩放后须全所统一。

**发生可能性 L（1-5）**

| 分值 | 锚点 | 参考依据 |
|---|---|---|
| 1 | 同行业 5 年内无案例，控制健全且经测试 | COSO ERM 2017 风险偏好校准 |
| 2 | 同行业偶发，本企业 3~5 年内无案例 | — |
| 3 | 本企业 1~2 年内发生过苗头或一般性问题 | 内审发现/监管检查通报 |
| 4 | 本企业年内已发生，或同行业高发 | ACFE：组织年均约 5% 收入流失于舞弊，提示频发常态 |
| 5 | 已多次发生或正在发生，相关控制基本失效 | — |

**经济损失（1-5）** —— 锚：国资委《中央企业违规经营投资责任追究实施办法》资产损失分级（2026-01-01 施行）；国务院令第 493 号直接经济损失等级

| 分值 | 锚点 | 权威依据 |
|---|---|---|
| 1 | <100 万元：未达"一般资产损失"标准，企业内部可消化 | 国资委办法（一般以下） |
| 2 | 100~500 万元：构成"一般资产损失" | 国资委办法：<500 万为一般 |
| 3 | 500~5000 万元：构成"较大资产损失"；493 号令"较大事故"直接损失（1000~5000 万）落于本档 | 国资委办法；国务院令第 493 号 |
| 4 | 5000 万~1 亿元：构成"重大资产损失"；493 号令"重大事故"量级 | 国资委办法：≥5000 万为重大；493 号令 |
| 5 | ≥1 亿元：493 号令"特别重大事故"直接损失量级，危及企业生存 | 493 号令第三条 |

**合规法律（1-5）** —— 锚：《个人信息保护法》第 66 条、《数据安全法》第 45 条、《网络数据安全管理条例》、GDPR 第 83 条、国资委"不良后果"三档

| 1 | 内部制度瑕疵，责令整改即可，无外部后果 | — |

| 3 | 一般行政处罚，罚款 100~1000 万元；责任人被处分 | 数安法第 45 条（≤1000 万）；网数条例第 56 条 |
| 4 | 情节严重：罚款 1000~5000 万元或上年度营业额 5%（个保法顶格）；GDPR 顶格 2000 万欧/全球营业额 4% 同档 | 个保法第 66 条第二款；GDPR Art.83 |
| 5 | 刑事责任移送、责令停业/吊销执照；国资委"重大不良后果"（影响社会与国家层面） | 国资委办法不良后果分级；刑法/监察法管辖 |

**运营中断（1-5）** —— 锚：国务院令第 493 号事故等级 + ISO 22301 业务连续性 RTO 分级

| 分值 | 锚点 | 权威依据 |

| 1 | 局部岗位受阻，当日恢复（RTO<8h），无人员伤害 | ISO 22301 恢复目标分级 |
| 2 | 单部门中断，RTO 1~3 天；轻微伤害事件 | ISO 22301 |
| 3 | 跨部门/跨区域中断，RTO 3~30 天；或 493 号令"一般事故"（<3 人死亡，直接损失<1000 万） | 493 号令第三条 |
| 4 | 核心业务瘫痪 1~6 个月；或"较大/重大事故"量级（3~30 人死亡，损失 1000 万~1 亿） | 493 号令第三条 |
| 5 | 集团级核心业务瘫痪超 6 个月；或"特别重大事故"（≥30 人死亡或≥1 亿元损失） | 493 号令第三条 |

**声誉舆情（1-5）** —— 锚：国资委"不良后果"三档（影响层面：涉事企业→行业/央企整体→社会和国家）× 传播层级

| 分值 | 锚点 | 权威依据 |
|---|---|---|
| 1 | 无外部感知，仅内部知晓 | — |

| 3 | 行业内流传、省级媒体或行业监管通报 | 国资委：较大不良后果 |
| 4 | 全国性媒体报道、上级机关通报批评，资本市场负面反应（评级下调/股价波动） | 国资委：较大~重大不良后果 |

| 分值 | 锚点 | 权威依据 |

### 3.3 控制有效性评分与折减

每条风险可挂 **1~N 条控制点**（如"网银双人复核""权限季度复核"），每条按 1-5 打有效性分，
并标记**是否关键控制**：

| 最弱控制分 | 折减系数 | 含义 |
|---|---|---|
| 1 | 0% | 控制形同虚设 |
| 2 | 15% | 控制薄弱 |
| 3 | 40% | 控制基本存在但有明显缺陷 |
| 4 | 55% | 控制较好，偶有例外 |
| 5 | 70% | 控制健全且有效执行 |

**关键控制与短板效应**：剩余风险按该风险**关键控制点的最低分**取折减系数；
若未标记任何关键控制，退回按全部控制点最低分。只评估"最弱一环"符合内审
木桶原理——一条关键控制失效，整项风险即不能视为受控。

**控制挽回率** = (固有 − 剩余) / 固有，衡量控制环境化解风险的比例。
按领域汇总后（汇总页领域表 / 报告脚本领域排名），可直接用于展示内审与
控制体系的价值："资金活动领域控制挽回率 55%，即控制措施化解了过半的固有风险敞口。"

### 3.4 风险领域体系（对齐内部审计准则框架）

领域分类参照两份权威框架：**《企业内部控制应用指引》（18 项）** 提供业务循环颗粒度，
**《中央企业全面风险管理指引》** 提供风险大类（战略/市场/财务/运营/法律）。
归并为 **4 大类 × 12 领域**：

| 大类 | 领域 | 对应内控应用指引 |
|---|---|---|
| 战略与治理 | 战略与投资 | 发展战略 |
| 战略与治理 | 治理与决策 | 组织架构、"三重一大"决策制度 |
| 财务 | 资金活动 | 资金活动（筹资/投资/营运） |
| 财务 | 财务报告与税务 | 财务报告、全面预算 |
| 财务 | 资产管理 | 资产管理（存货/固定资产/无形资产） |
| 运营 | 采购与外包 | 采购业务、业务外包 |
| 运营 | 合同管理 | 合同管理 |
| 运营 | 工程项目 | 工程项目 |
| 运营 | 人力资源 | 人力资源 |
| 运营 | 信息系统 | 信息系统 |
| 合规与安全 | 合规与法律 | 法律风险、合规管理 |
| 合规与安全 | 安全环保 | 安全生产、环境保护、社会责任 |

> 指引中的"市场风险"在审计语境下并入运营类各领域（价格波动体现在具体业务影响打分中）。
> 每个领域在参数配置页有专属权重行（见 4.2），体现领域风险画像差异。

### 3.5 风险等级（默认阈值，可调）

| 等级 | 剩余风险分 | 颜色 | 审计频次建议 |
|---|---|---|---|

### 4.3 风险登记册（日常主战场）

数据区从第 4 行开始，已预留至 200 行。

| 列 | 字段 | 录入/公式 | 说明 |
|---|---|---|---|
| A | 风险编号 | 录入 | 建议 R001、R002… 全簿唯一 |
| B | 风险名称 | 录入 | 简短名词短语 |
| C | 所属领域 | 录入（下拉） | 覆盖战略与治理、财务、运营、合规与安全 4 大类 12 领域（见 3.4） |
| D | 风险描述 | 录入 | 一句话描述风险情形 |
| E | 责任部门 | 录入 | |
| F | 评估期间 | 录入（下拉） | 默认 2025H2 / 2026H1 |
| G | 发生可能性 | 录入（1-5） | 下拉限选，超范围拒绝 |
| H~O | 八维影响 | 录入（1-5，可留空） | 经济损失/合规法律/运营中断/声誉舆情/舞弊风险/战略影响/数据安全/健康安全 |
| P | 综合影响 | 公式 | 八维加权与一票否决下限取较大值 |
| Q | 固有风险 | 公式 | 发生可能性 × 综合影响 |
| R | 关键控制分 | 公式 | 关键控制点最低分；无关键标记时退回全部控制点最低分 |
| S | 折减系数 | 公式 | 按 R 列控制分查折减映射 |
| T | 剩余风险 | 公式 | 固有风险 × (1−折减系数) |
| U | 剩余等级 | 公式 | 按阈值映射极高/高/中/低/极低 |
| V | 影响档 | 公式 | 综合影响四舍五入后的热力图横轴辅助值 |
| W | 固有点 | 公式 | 固有风险四舍五入后的辅助值 |
| X | 建议审计频次 | 公式 | 按剩余等级生成频次建议 |
| Y | 控制挽回率 | 公式 | (固有−剩余)/固有，百分比显示 |
| Z | 打分依据 | 录入 | 证据导向：引用审计发现、监管动态、量化数据，支撑可能性与八个影响维度的复核 |

登记册 P~Z 列与工作簿表头逐列对应，公式列请勿手工覆盖。

**日常操作**：新增一行 → 填 A~O 与 Z → 计算列自动出结果。删除风险时建议整行删除
（同时到「控制措施表」清理其控制点）。

### 4.4 控制措施表

数据区从第 4 行开始，已预留至 150 行。

| 列 | 字段 | 说明 |
|---|---|---|
| A | 控制编号 | C001、C002… |
| B | 关联风险编号 | 下拉引用登记册已有编号 |
| C | 评估期间 | 必须与所关联风险的期间一致 |
| D | 控制点描述 | 具体控制活动名称 |
| E | 有效性评分 | 1-5，下拉限选 |
| F | 关键控制 | 是/否 下拉；剩余风险按关键控制的最低分折减 |

> 一条风险挂几条控制点不限；**剩余风险只看关键控制中最弱的一条**
> （未标记关键控制时退回全部控制点取最低）。

### 4.5 热力图页

- 右上角 **C3 单元格**为期间筛选器（2025H2 / 2026H1 / 全部），两张矩阵联动；
- **固有矩阵**：格内数字 = 落入该（可能性 × 影响档）格的风险数量；影响档由精确综合影响四舍五入得到，底色按格子固有分值；
- **剩余矩阵**：格内数字 = 该位置风险的剩余分**均值**，底色随阈值联动；
- 单条风险的精确剩余分请看「汇总与优先级」页或登记册 T 列。

### 4.6 汇总与优先级页

- 期间与热力图页联动（B2 自动镜像）；
- **领域汇总表**：各领域的风险数、平均/最高剩余分、极高/高风险数、**平均控制挽回率**；
- **优先级清单**：当前筛选期间的风险按剩余风险降序连续排名（同分时按登记册行序稳定排序），
  含固有、最弱控制、剩余、等级色块、建议频次，可用 Excel 筛选按领域/部门过滤，
  直接作为年度审计计划编制底稿。

### 4.7 环境要求

- **Excel 2019 / Microsoft 365 及以上**（公式使用 MINIFS、MAXIFS）；
- 纯公式实现，**无需启用宏**；WPS 表格对 MINIFS 支持不全，不建议使用。

## 5. Python 脚本操作指南

### 5.1 环境准备

- Python 3.10+（开发验证于 3.13）
- 依赖仅两个：`pip install matplotlib openpyxl`
- 中文图表字体使用微软雅黑（Windows 自带）

### 5.2 命令一览

| 命令 | 作用 | 常用参数 |
|---|---|---|
| `python tools\build_excel.py` | 重建含示例数据的工作簿（**会覆盖**现有 xlsx） | 无 |
| `python tools\export_from_excel.py` | xlsx → CSV 对 + config.json | `--xlsx` 指定其他工作簿路径 |
| `python tools\generate_report.py` | CSV → PNG 图集 + PDF 简报 | 见下 |
| `python tools\sample_data.py` | 重置示例数据（CSV + 网页内置数据） | 无 |
| `python -m unittest discover -s tests` | 运行 24 项评分模型测试 + 发布一致性测试 | 无 |

`generate_report.py` 参数：

| 参数 | 默认 | 说明 |
|---|---|---|
| `--period` | 字典序最大的期间 | 基准评估期间 |
| `--compare` | 另一期间 | 对比期间；`--compare none` 关闭趋势图 |
| `--data-root` | `data/export` | 数据根目录 |
| `--outdir` | `output` | 输出目录 |
| `--sensitivity` | 关闭 | 附加权重敏感性分析：各维度权重 ±20% 扰动后重算排名，输出 TOP8 排名矩阵图，检验优先级排序是否为权重选择的偶然产物 |

示例：

```powershell
# 以 2026H1 为主、2025H2 为对比期（默认行为）
python tools\generate_report.py

# 只出 2025H2 单期（无趋势图）
python tools\generate_report.py --period 2025H2 --compare none

# 附加权重敏感性分析（汇报答辩用）
python tools\generate_report.py --sensitivity
```

### 5.3 输出物说明（output/ 目录）

| 文件 | 内容 | 汇报用法 |
|---|---|---|
| `{期间}_inherent_heatmap.png` | 固有风险气泡热力图 | 展示"风险原貌" |
| `{期间}_residual_heatmap.png` | 剩余风险气泡热力图 | 展示"控制成效" |
| `{期间}_domain_distribution.png` | 领域 × 剩余等级堆叠条形图 | 展示风险分布结构 |
| `trend_{A}_vs_{B}.png` | 两期剩余风险哑铃图 TOP12 | 展示整改成效与恶化预警 |
| `transition_{A}_vs_{B}.png` | 两期等级迁徙矩阵（改善/恶化/持平计数） | 审计委员会汇报常用 |
| `sensitivity_{期间}.png` | 权重敏感性排名矩阵（`--sensitivity` 时） | 回应"权重凭什么这么定"的答辩材料 |
| `executive_report_{期间}.pdf` | 高管简报：指标卡（含控制挽回率）+TOP10 表 + 图集 | 直接投屏/发送 |

气泡图读法：横轴=综合影响档（精确综合影响四舍五入），纵轴=发生可能性，气泡颜色=该风险自身等级，
背景格色=该格固有分值档位，气泡内为风险编号（同格多条自动错开）；
精确综合影响见网页悬停提示、PDF 封面 TOP10 表或 Excel 登记册，编号与名称对照见 Excel 优先级清单。

### 5.4 内置交叉验证

`generate_report.py` 每次运行末尾打印**剩余风险 TOP8 明细表**（可能性/影响/固有/控制分/剩余/等级）。
该数值与 Excel 登记册 P~U 列、网页端优先级清单三者必须一致——这是验收金标准。

## 6. 网页端操作指南

打开 `web/risk_heatmap.html` 即用。**零依赖、离线可用**，数据保存在浏览器 localStorage。

### 6.1 界面分区（自上而下）

1. **顶栏**：评估期间选择、对比期间选择、载入内置示例、打印/存 PDF；
2. **指标卡**：风险总数、平均剩余分、极高风险数、高风险数；
3. **双热力图**：左固有右剩余；气泡悬停显示摘要，**点击气泡（或优先级清单行）打开右侧详情栏**——完整档案含打分依据、可能性与八个影响维度、计算过程、控制点清单（关键标记）、两期对比；
4. **两期趋势对比**：哑铃图（TOP12 变化幅度）+ 全量变化表 + **等级迁徙矩阵**（对角线=持平，左下=改善，右上=恶化）；
5. **年度审计优先级清单**：排名、等级色块、挽回率、建议频次；
6. **数据维护**（不打印）：CSV/JSON 导入、风险条目表单、控制点管理（含关键控制标记）、风险清单；
7. **评分参数**（不打印）：权重（实时合计校验）、阈值、折减映射、一票否决系数、**分领域权重矩阵**。

### 6.2 数据导入 / 导出

- **导入**：「数据维护」区依次选择 `risks.csv`、`controls.csv`、`config.json`（可选）。
  按文件内 `period` 列自动归入对应期间，可一次导入多期文件实现趋势对比；
- **导出**：优先级清单下方三个按钮，导出当前期间的 risks.csv / controls.csv / config.json
  （带 BOM，Excel 直接打开不乱码），可与 Excel 真源双向核对。

### 6.3 在线编辑

- **新增风险**：填编号（留空自动顺延 R00x）、名称、领域、部门、描述、可能性与八个影响维度 → 「保存风险」；
- **修改风险**：清单中点「编辑」，表单载入后修改再保存；
- **删除风险**：点「删除」，其控制点一并删除；
- **维护控制点**：右上选择所属风险 → 填描述、选有效性分、选是否**关键控制** → 「添加」；
  已有控制点可改分/改关键标记/删除。

所有改动即时重算并自动保存（刷新页面不丢失）。

### 6.4 调整评分参数

「评分参数」面板：八个权重输入框下方实时显示合计（绿色=合法，红色=≠1）；
阈值与折减系数修改后全页即时重算。与 Excel 参数配置页等效，两边改任一边注意同步。

### 6.5 汇报打印

点击顶栏「打印 / 存 PDF」→ 浏览器打印对话框 → 选择"另存为 PDF"。
打印视图自动隐藏编辑与导入区，保留指标卡、双热力图、趋势、优先级清单，横版效果最佳。

### 6.6 数据安全

- 换电脑/换浏览器需重新导入 CSV；
- 「清空本机数据」恢复到内置示例状态，操作前请确认已导出。

## 7. 数据流转与一致性原则

```
            ┌──────────── 唯一真源 ────────────┐
            │      audit_risk_register.xlsx   │
            └───────┬──────────────┬──────────┘
        export_from_excel.py     （手工另存/对照）
            ┌───────┴────────┐     ┌──────┴──────┐
            │ risks.csv      │     │ 网页端导入    │
            │ controls.csv   │ ──→ │ localStorage │
            │ config.json    │     └─────────────┘
            └───────┬────────┘
             generate_report.py
            ┌───────┴────────┐
            │ PNG ×4 + PDF   │
            └────────────────┘
```

**三条铁律**：

1. **Excel 是唯一真源**。网页 localStorage 只是草稿，定期以 Excel 导出为准；
2. **CSV 是唯一交换格式**。三端数值一致性由共享公式保证，`generate_report.py`
   末尾的 TOP8 表是验收依据；
3. **参数改动要三端同步**。权重/阈值/折减在 Excel「参数配置」或网页「评分参数」
   任一处修改后，记得导出/导入 config.json 对齐另一端。

## 8. 常见任务手册

### 8.1 新增一条风险

Excel：登记册第一个空行填 A~O 与 Z 列 → 控制措施表为它挂控制点 → 完成。
网页端：「数据维护」表单填写后保存（别忘了补控制点，否则不折减）。

### 8.2 开始新一期评估（如 2026H2）

1. 「参数配置」页 I 列期间清单的空行填入 `2026H2`（登记册、控制表、热力图下拉自动同步）；
2. 复制上期风险行，改 F 列为新期间，按本期情况更新 G~O 打分；
3. 控制措施表同理复制上期控制点并改期间、更新 E 列评分；
4. `python tools\export_from_excel.py` → 自动生成 `data/export/2026H2/`；
5. `python tools\generate_report.py` 自动识别最新期间并默认与上一期对比；
6. 网页端导入新 CSV 即可查看三期数据（趋势对比任选两期）。

### 8.3 调整权重 / 阈值 / 折减

Excel 参数配置页直接改 → 全簿自动重算 → 重新导出使 config.json 同步。
网页端在「评分参数」面板改。**注意**：权重合计≠1 时导出脚本会拒绝执行并提示。

### 8.4 换行业 / 换领域适配

1. `tools/common.py` 修改 `DOMAINS` 领域清单与 `DOMAIN_CATEGORY` 大类映射；
2. Excel 登记册 C 列数据验证同步修改来源列表；参数配置页权重矩阵按新领域增删行
   （注意同步修改登记册 P 列公式中的矩阵引用范围 $A$26:$I$38）；
3. 网页端修改脚本顶部 `DOMAINS` 常量与 `DOMAIN_CATEGORY`；
4. 替换 `tools/sample_data.py` 中的示例风险后运行 `python tools\sample_data.py`。
   评分模型本身无需任何改动。

### 8.5 增减影响维度（进阶）

涉及三处联动：`tools/common.py` 的 `DIMS`/`DIM_LABELS` 与默认权重；
Excel 参数配置权重区、登记册 P 列公式；网页端 `DIMS` 常量与表单字段。
建议由 IT 支持人员操作，改完跑一遍第 5.4 节交叉验证。

### 8.6 只想出某一条风险的说明材料

网页端导入数据后，在优先级清单用浏览器页内查找（Ctrl+F）定位该风险，
配合热力图悬停明细截屏即可。

## 9. FAQ 与故障排查

**Q1：打开 xlsx 提示公式错误 / 计算列全空？**
Excel 版本低于 2019（缺 MINIFS/MAXIFS）。请升级 Office 或使用网页端。

**Q2：导出脚本报"权重之和必须为 1"？**
参数配置页 B11 合计格变红。把八个权重改到合计=1（如 25%+20%+12%+10%+10%+10%+8%+5%）再导出。

**Q3：某条风险的剩余分等于固有分？**
该风险在当前期间没有控制点，或控制措施表的期间与风险的期间不一致（短板查找按"编号+期间"匹配）。

**Q4：网页打开后图表空白？**
① 点「载入内置示例」；② 若导入过数据，检查 CSV 是否选对（risks 与 controls 分开两个输入框）；
③ 极端情况下点「清空本机数据」重置。

**Q5：CSV 用 Excel 打开中文乱码？**
本项目导出的 CSV 已带 BOM 不会乱码；若你自己另存的文件乱码，另存为时选"CSV UTF-8"。

**Q6：图表中文显示为方框？**
非 Windows 系统需安装微软雅黑，或修改 `tools/generate_report.py` 顶部
`font.sans-serif` 为本机可用中文字体（如思源黑体）。

**Q7：热力图上多个气泡挤在一格？**
同影响档风险自动错开摆放；精确综合影响请看登记册或网页悬停提示，精确剩余分请看优先级清单或登记册。

**Q8：想撤销网页端的修改？**
未导出前可点「清空本机数据」回示例状态；正式数据请始终以 Excel 为准重新导入。

**Q9：build_excel.py 会覆盖我填的数据吗？**
会。它用于首次生成或重置演示。日常维护请直接在现有 xlsx 上操作，不要重跑该脚本。

**Q10：能多人同时维护吗？**
当前为单机文件方案。多人协作建议：Excel 放共享盘由专人维护，其余人只读消费
CSV/报告；后续可基于 `data/export` 的 CSV 接口接入业务系统（预留了 Risk as Code 升级路径）。

**Q11：关键控制标记有什么讲究？**
每条风险建议只把"一旦失效该风险即不受控"的核心控制标为关键（通常 1~2 条）。
标记越多，短板效应覆盖面越大，剩余风险越高——这是有意的保守取向。
全部不标记时退回"全部控制点取最低"，相当于把所有控制都当关键。

## 11. Windows 桌面端：审计报告风险评估

### 11.1 适用范围与安装

桌面端仅支持 Windows（Windows 10/11 x64）。应用本身采用每用户安装，不需要管理员权限；安装后的应用自带 Python 运行环境，不需要另装 Python，也不要求审计人员使用命令行。首次启动需要 Microsoft Edge WebView2 Runtime；安装程序检测不到时会停止并提示先安装该运行时。若系统缺少锁定版本的 Microsoft Visual C++ Runtime，安装器会释放微软官方签名的 `VC_redist.x64.exe`，由该前置组件单独请求 UAC 并完成机器级安装；应用主体仍不提权。

支持文字型 PDF、扫描 PDF 和 DOCX；不支持 `.doc`。加密文件、损坏文件、超出大小或页数上限的文件会被拒绝。项目不提供知识库、RAG、向量检索或报告问答，也不会把历史报告做成可检索语料库。

仓库自带的报告、模型响应和验收输出全部是虚构测试数据，仅用于非生产验证。真实使用前，应由本单位确认报告上传授权、模型服务的数据处理条款和保密要求。

### 11.2 第一次配置模型

打开“报告分析”，在第一步填写模型名称、Base URL、模型名和 API Key，并按服务能力勾选“支持视觉”，然后依次点击“保存模型设置”和“测试连接”。模型服务必须提供 OpenAI 兼容接口；公网地址使用 HTTPS，本机回环服务可使用 HTTP。

API Key 保存在 Windows 凭据管理器（Windows Credential Locker），不会写入本地 SQLite、日志或导出的工作簿。模型名称、Base URL、模型名和是否支持视觉会保存在本地状态库。保存或修改配置后，必须重新点击“测试连接”；验证状态同时绑定配置内容和当前密钥，未验证或已变化的配置不能开始分析。

使用云端模型时，本地提取出的报告文字、用于匹配的最小风险目录 `risk_id/name/domain/description` 会发送给所配置的服务方；只有 OCR 仍无法可靠识别且用户所选模型支持视觉时，相应问题页图片才会发送。责任部门、既有评分、控制措施和原台账打分依据留在本地，不进入模型请求。选择模型服务前，应先完成单位内部的数据出境、保密和供应商审批。

### 11.3 四步流程

1. **选择报告、工作簿与模型**：选择 `.pdf` 或 `.docx`，再选择现行正式工作簿，填写评估期间，并选择已测试的模型配置。模型匹配目录、分析任务、变更预览和最终写入绑定同一工作簿及其哈希；分析期间不能换成另一份台账。
2. **自动提取与分析**：处理顺序固定为“本地文本提取 → 自动 OCR → 可选视觉模型兜底 → 大模型判断”。有可用文本的页面不会为了识别而额外调用视觉模型。
3. **复核审计发现**：模型生成精简的待复核记录。用户从报告快照重新查看 PDF 页面或 Word 文本/图片 OCR 原文，核对涉及单位、金额及每个维度的独立证据；可以修改、拆分、合并、接受或排除。合并会保留全部成员 ID 和来源证据，之后再拆分或排除也会处理整个合并关系。模型输出只是建议，不能自行批准发现，也不能直接决定最终分数。
4. **预览并写入**：用户人工确认风险映射、责任部门、可能性、八个影响维度、评估期间、当前控制和整改状态，然后查看绑定工作簿的变更预览。新风险必须填写责任部门；合并到现有风险时默认读取台账中的责任部门，但仍需人工确认。整改状态写入打分依据，不改变 v1.2 的列结构。确认后才生成版本化工作簿和 CSV 导出，最终评分仍由 `tools/common.py` 的确定性规则计算。

历史审计发现不能单独证明当前剩余风险。历史报告只能说明报告形成时的事实；若没有重新确认当前控制、整改执行和现时业务环境，不得把历史控制缺陷直接当作当前控制分。

### 11.4 输出文件与正式真源

桌面端不覆盖原工作簿。默认在所选工作簿同目录生成 `audit_risk_register_yyyyMMdd_HHmm.xlsx`，同时生成同名 `_data_export` 目录。若目标名称已存在，系统会停止，不会静默替换。

新文件最初只是“候选版本”。建议由风险台账责任人完成以下检查：核对变更预览与已接受发现；抽查证据、风险编号、控制措施和评分；用现有导出/报告流程复算；记录复核人和审批记录。只有完成本单位规定的复核审批后，才能将该版本指定为新的正式真源。原始报告和原工作簿应按档案制度另行保存。

### 11.5 本地状态、隐私与删除本地任务

本地状态位于 `%LOCALAPPDATA%\RiskAssessmentHeatMap`：`state.db` 只保存精简的任务元数据、待复核发现和模型配置；`temp` 用于分析期间的规范化文字及页面图片。任务完成、取消或失败清理后，临时内容会被删除；若界面提示残留位置，应由 IT 人员核对该精确目录后处理。

当前版本不提供逐条删除已留存任务记录的按钮。需要删除本地任务时，先关闭应用并确认已保存所需的版本化工作簿，然后删除 `%LOCALAPPDATA%\RiskAssessmentHeatMap\state.db`；这会一次性删除全部本机任务、待复核发现和模型配置元数据。API Key 不在该文件中，如需一并删除，应在 Windows“凭据管理器”中删除本应用对应凭据。不要删除原始审计报告或已审批工作簿来代替清理应用状态。

日志不记录 API Key、报告正文、完整模型请求或完整模型响应。应用也不保存报告副本。若使用云端模型，传输边界以所配置服务商为准；“本地提取”不等于“大模型分析全程离线”。

### 11.6 重试与常见错误

- “原始报告不可用或已变更”：重新选择报告；系统会校验文件哈希，不能用同名的另一份文件替代。
- “模型配置或连接不可用”：检查 Base URL、模型名、API Key、网络和服务端兼容性，再点“测试连接”。配置或密钥变化后必须重测。模型失败后只重试失败阶段，已经完成的提取和人工修改会尽量保留。
- “提交预览已失效”：工作簿或复核决定在预览后发生变化，重新生成预览再确认。
- “输出文件已存在”：保留已有文件，调整输出时间或目录后重试。
- OCR 失败或页面质量过低：支持视觉的模型可处理被标记的问题页；不支持视觉时，该页必须保留为需人工复核，不能凭空补写事实。
