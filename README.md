# 审计风险评估热力图谱

> 从审计报告到风险图谱：把报告中的问题与证据转成经过人工确认、可以追溯来源的结构化风险信息。

当前版本：`1.2`

Windows 桌面发行版：`1.2.2`（风险评分模型和工作簿格式继续使用 1.2）。

Risk Assessment Heat Map 面向内部审计人员。Windows 桌面端负责识别报告、组织证据和形成评估批次；项目原有的确定性评分引擎负责计算风险分数；Excel、网页和图表负责维护、展示与汇报。

首版聚焦一个被审计主体。一个单主体信息目录只能对应一个主体，使用者可以从目录中选择一份或多份报告形成风险图谱。

## 适合谁使用

- 需要从 PDF、DOCX 审计报告中整理风险事项的内部审计人员。
- 需要合并多份报告证据，同时保留报告名称、页码和事实依据的复核人员。
- 需要沿用现有风险分类、八维影响评分、控制折减和 Excel 风险登记册的项目团队。
- 需要在生成正式结果前保留人工判断与变更预览的使用者。

本项目不是自动出具审计结论的系统。模型输出只是建议，风险映射、评分、当前控制和整改状态必须经过人工确认。

## Windows 桌面端快速开始

桌面端仅支持 Windows 10/11 x64。安装后的应用不要求使用者另装 Python，也不要求使用命令行。如果系统缺少指定版本的 Microsoft Visual C++ Runtime，安装程序会调用微软官方前置组件；界面使用系统 WebView2 运行时。

从 [GitHub Release v1.2.2](https://github.com/Jayliu2025-vip/Risk-Assessment-Heat-Map/releases/tag/v1.2.2) 下载 Windows x64 安装包及 SHA-256 校验文件。安装程序支持覆盖旧版升级，保留模型配置和报告目录；卸载删除程序文件，保留用户数据与凭据。维护者可以按照后文的“开发与验证”说明自行构建。

### 1. 建立单主体信息目录

首次打开桌面端时，选择一个用于保存结构化信息的目录，并填写唯一的被审计主体。目录产生报告信息后，不能静默改换为另一个主体。

生产桌面端默认不加载示例，也不提供示例入口。更准确地说，桌面端不自动加载示例数据；仓库中的虚构测试数据仅用于非生产自动验收。

### 2. 添加并复核报告

选择报告文件、审计项目、模型配置和现行正式工作簿。当前支持文字型 PDF、扫描 PDF 和 DOCX，不支持 `.doc`。

首次配置模型时，展开“连接大模型”，选择服务商、粘贴 API 密钥，点击“保存并验证”。内置 DeepSeek、阿里云百炼中国大陆按量付费、GLM（智谱）和 Kimi 开放平台 API 预设，自动填写服务地址、配置名称及默认模型；其他兼容服务直接填写服务地址即可。密钥输入框旁提供官方获取指南。预设不代表模型分析质量已经过实测，实际连接以验证结果为准。

只需一套模型配置。保存时使用小测试图片自动检查当前模型的图片能力；支持时会自动读取文字识别失败的报告页，不需要图片开关或第二套模型。不支持或暂未检测成功时显示简短提示，继续使用文字识别。

修改已有配置时会自动回填字段，密钥留空表示保留；改换服务地址需要重新粘贴对应密钥。每次打开软件后，已保存配置显示“待验证”，验证成功后才能开始识别。操作步骤和错误处理见[使用手册](docs/使用手册.md#112-第一次设置主体目录与模型)。

识别顺序固定为：

```text
本地文本提取 → 自动 OCR → 可选视觉模型兜底 → 大模型判断
```

模型通过 OpenAI 兼容接口调用。为了最小化传输范围，现有风险目录只向模型提供 `risk_id/name/domain/description`；既有评分、责任部门、控制措施和评分依据留在本地。API Key 保存在 Windows 凭据管理器中，不写入报告目录、SQLite 或日志。

模型返回的风险事项处于待复核状态。使用者需要检查来源摘录、页码、风险映射、可能性和八个影响维度，确认后才能保存到报告目录。

### 3. 选择报告形成评估批次

报告目录以上传日期作为主要日期，识别出的正式报告日期作为附加信息。使用者可以按上传日期和审计项目筛选，再选择一份或多份报告创建风险评估批次。

不同报告中的问题可能指向同一项风险。系统会进入“相似发现处理”，由使用者决定如何纳入本次评估。

推荐选择“为同一风险的两条证据”：风险图谱只形成一项风险，但保留每份报告、每个页码和每条事实依据。系统不会删除原发现，也不会把不同模型建议简单平均。

### 4. 确认当前情况并生成结果

历史报告只能证明报告形成时的事实，不能单独证明当前剩余风险。形成正式结果前，使用者必须重新确认：

- 风险映射与风险名称；
- 发生可能性和八个影响维度；
- 责任部门；
- 当前控制及关键控制点；
- 整改状态和评分依据。

系统随后使用项目既有的确定性规则重新计算影响、固有风险、控制折减、剩余风险和风险等级。写入前必须查看变更预览；确认后生成新的版本化工作簿及导出目录，不覆盖原工作簿。

## 报告目录如何工作

报告完成识别和人工复核后，目录只保留跟项目相关的结构化信息，包括：

- 报告名称、审计项目、上传日期和可选报告日期；
- 风险事项、关键事实、来源页码和必要摘录；
- 建议评分、人工复核结果及对应的报告版本；
- 已完成评估批次使用的报告版本和证据来源。

目录支持单条删除和“清空报告列表”。普通删除会把结构化报告记录移入当前信息目录内的可恢复回收站，不删除原始报告、历史批次或已经生成的工作簿。损坏的派生索引可以根据权威报告记录重建。

## 同一风险的多份证据

“为同一风险的两条证据”表示证据归并，不是删除或覆盖：

```text
报告 A 第 12 页 ─┐
                  ├─ 风险 R004 ─ 风险图谱中的一项风险
报告 B 第 7 页  ─┘
```

每条证据仍然保留自己的报告来源、页码和事实依据。当前评分由使用者结合全部证据重新判断；模型建议仅供参考。“本次暂不处理”的发现不会进入当前风险决策。

## 数据与隐私边界

- 原始 PDF 或 DOCX 只用于本次本地处理，报告目录不会复制原始报告。
- 目录不保存原文件绝对路径、完整提取正文、页面图片或 API Key。
- 临时提取文件按任务隔离并在流程结束后清理。
- 模型只接收完成当前判断所必需的报告内容和最小风险目录。
- API Key 使用 Windows 凭据管理器保存，错误信息和日志不得回显密钥、原路径或完整报告正文。
- 删除报告目录中的结构化记录，不等于删除使用者自行保管的原报告。
- 正式写入始终生成带时间戳的新工作簿，不覆盖原工作簿。

详细操作与保存位置见[完整使用手册](docs/使用手册.md)。

## 评分与人工责任

模型负责识别、归纳和提出建议，正式分数由 `tools/common.py` 的确定性规则重新计算。

```text
综合影响 I = max(Σ(wᵢ×维度ᵢ)/Σ(已评分维度的wᵢ), 一票否决系数 × 最高维度分)

固有风险 = 发生可能性 L × 综合影响 I
控制分   = 关键控制点最低分；无关键标记时取全部控制点最低分
剩余风险 = 固有风险 × (1 − 控制折减系数)
```

风险领域体系为 4 大类 12 领域。八个影响维度为经济损失、合规法律、运营中断、声誉舆情、舞弊风险、战略影响、数据安全和健康安全，均按 1–5 分评估。权重矩阵、等级阈值、控制折减映射和一票否决系数可以配置。

默认风险等级为：极高 `≥20`、高 `≥12`、中 `≥6`、低 `≥3`、极低 `<3`。

## 当前支持与暂不支持

当前支持：

- Windows 10/11 x64 桌面端；
- 文字型 PDF、扫描 PDF 和 DOCX；
- OpenAI 兼容的云端或本地模型接口；
- 单主体信息目录；
- 按上传日期和审计项目筛选报告；
- 一份或多份报告组成评估批次；
- 同一风险保留多报告、多页码、多事实证据；
- 版本化 Excel、CSV、网页风险图谱和汇报图表。

当前不支持：

- `.doc` 文件；
- 集团组织树、跨主体报告选择和集团汇总风险图谱；
- 无人工复核的自动正式评分；
- 自动审批或自动发布审计结论；
- 知识库、RAG、向量检索和历史报告聊天。

项目不提供知识库、RAG、向量检索或报告问答。集团化能力属于后续规划，不应把多个主体的报告放入同一个首版信息目录。

## 网页端与 Excel/Python 工作流

Windows 桌面端是审计报告识别和批次评估的推荐入口。项目仍保留原有 Excel、Python 和离线网页链路：

1. `audit_risk_register.xlsx` 是正式风险数据真源；
2. `tools/export_from_excel.py` 把工作簿导出为 CSV 和配置文件；
3. `tools/generate_report.py` 生成热力图、趋势图和 PDF 简报；
4. `web/risk_heatmap.html` 可以离线打开并导入同一份数据。

浏览器模式同样从空状态开始，但允许使用者显式加载虚构示例用于演示。示例数据不是生产数据，也不能解锁桌面端结果。

## 输出文件

| 输出 | 用途 |
| --- | --- |
| `audit_risk_register_yyyyMMdd_HHmm.xlsx` | 经人工确认后生成的版本化风险工作簿 |
| `risks.csv`、`controls.csv`、`config.json` | 网页和 Python 图表使用的交换数据 |
| `*_inherent_heatmap.png` | 固有风险热力图 |
| `*_residual_heatmap.png` | 控制折减后的剩余风险热力图 |
| `*_domain_distribution.png` | 风险领域与等级分布 |
| `trend_*.png`、`transition_*.png` | 跨期间趋势与迁徙分析 |
| `executive_report_*.pdf` | 指标、优先级和图表组成的管理层简报 |

## 开发与验证

桌面端构建使用 CPython 3.13.14 x64。安装依赖并运行测试：

```powershell
py -3.13 -m venv .venv-desktop
.\.venv-desktop\Scripts\python.exe -m pip install --upgrade pip
.\.venv-desktop\Scripts\python.exe -m pip install -r requirements-build.txt
npm ci

.\.venv-desktop\Scripts\python.exe -m unittest discover -s tests -v
npx playwright test tests/e2e --reporter=line
```

当前仓库已经验证：

- 268 项 Python 测试通过；
- 15 项 Playwright 流程通过；
- 进程级离线合成验收通过；
- 当前主机上的全新安装、1.2.1 覆盖升级至 1.2.2、安装后图片检测与识别、配置保留和卸载清理通过。

单独的无 Python 全新 Windows 环境验收和物理断网观察仍未完成，因此不能把当前状态描述为所有目标环境均已完成发布验收。当前发行版见[发布说明与验收范围](docs/releases/v1.2.2.md)及[验收证据](docs/releases/v1.2.2-acceptance.json)，历史基线见[桌面端验收记录](docs/desktop-acceptance.md)。

构建 Windows 安装包：

```powershell
pwsh -NoProfile -ExecutionPolicy Bypass -File .\tools\build_desktop.ps1 `
  -PythonExe '.\.venv-desktop\Scripts\python.exe'
```

`build/`、`dist/` 和 `installer-output/` 是本地构建产物，不提交到 Git。
